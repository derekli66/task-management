# Workspace task reminders — acceptance summary

## Outcome

The plugin now exposes exact workspace-scoped unfinished-task counts and a compact reminder through Codex lifecycle hooks. Completed and cancelled tasks remain hidden by default.

The default reminder mode is `lifecycle`, covering `startup`, `resume`, `/clear`, and compaction. `always` additionally emits the same summary from the `Stop` hook after each assistant turn. Reminder mode is a per-machine preference; task state remains scoped to the canonical workspace path.

## Delivered behavior

- `task_list.summary.matching_total` and `summary.by_status` report exact filtered totals before pagination.
- The reminder reader opens SQLite with `mode=ro` and never creates or migrates storage.
- Reminders show at most five sanitized task titles and collapse the remainder.
- Stored titles appear only in the visible `systemMessage`; model-visible lifecycle context contains counts and a direction to query the MCP tool, not stored task text.
- Hook execution is bounded to two seconds and fails quietly when storage is absent, busy, or unsupported.
- The runtime installer preserves a valid reminder preference and accepts `--reminder-mode lifecycle|always`.

## Surface support and limits

Codex CLI and Codex local projects in the ChatGPT desktop app can use the installed plugin and local hooks. A new thread is required after installation, and the hook source must be trusted by the host. ChatGPT web/mobile, Codex cloud, regular chats without a local workspace, and the IDE extension do not gain access to this machine-local SQLite database.

This is a warning-style lifecycle message, not a native pinned task panel. Host UI rendering is controlled by Codex.
