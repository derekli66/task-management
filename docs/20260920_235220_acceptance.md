# Mutation-driven task reminders — acceptance summary

## Summary

The default reminder cadence is now event-driven: session start events still
load the current workspace state, and successful `task_create` / `task_update`
calls redraw it immediately. Unrelated assistant turns do not redraw the list.
The optional `always` mode still adds the existing end-of-turn reminder.

Successful mutation responses include a bounded `workspace_overview`, so the
skill can place the same compact summary at the end of the assistant response
without a second `task_list` call. This is also the fallback for the ChatGPT
desktop Codex UI, which currently runs the local hook but may not render its
`systemMessage` warning.

## Safety and behavior checks

- Hook matching is exact: `^mcp__tasks__task_(create|update)$`.
- The hook requires a recognized successful MCP result, a valid task snapshot,
  and a canonical tool-input workspace equal to the active workspace.
- MCP/domain errors, malformed results, cross-workspace calls, and idempotent
  create reuse fail closed without a redraw.
- Closing the final task emits `Tasks · 0 unfinished`, which semantically
  supersedes prior snapshots even if the host retains them in scrollback.
- Mutation warnings contain only `systemMessage`; they do not add developer
  context or start another model turn.
- The mutation tool result itself contains at most five sanitized titles and is
  model-visible. It replaces the former post-mutation `task_list` round trip.
- Parallel mutation events may each render the same final database snapshot.

## Surface limits

Interactive Codex CLI can render hook `systemMessage` warnings. Non-interactive
`codex exec` logs hook start/completion but does not print the warning body, so
the installed-launcher contract was checked separately. The ChatGPT desktop
Codex UI observed in this work loads hook context but does not currently show
the warning reliably. The bounded assistant-response summary therefore remains
necessary there. No supported surface gets a pinned or live task panel.

After this hook definition changes, a new thread is required and Codex must
trust the new hook hash before running it normally.
